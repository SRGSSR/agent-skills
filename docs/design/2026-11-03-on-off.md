# On / off per project

- Date: 2026-11-03
- Status: implemented (skills v0.2.0)
- Scope: `skills/project-phase/SKILL.md`, `skills/work-journal/SKILL.md`, README "Disable or uninstall"

## Why

The always-on behavior lives in the `AGENTS.md` blocks, not in the skill. Removing the skill leaves the behavior in place, and deleting the block by hand is not enough while the skill is installed: its description triggers on common phrases ("let's stop here", "we're just prototyping", a repo with `.ai/handoff.md`), and work-journal setup runs on the first journal entry in a repo without the block. So a deleted block can come back on its own.

## Decisions

- **`off` leaves a one-line marker** (`<!-- project-phase:off -->`, `<!-- work-journal:off -->`) in place of the block. It costs almost nothing in context and is the persistent signal "don't set up here". The marker lives in `AGENTS.md` because that file is already read on every task and is where the skill looks for its block.
- **While off, explicit requests are still served once**, without turning the skill back on, with a one-line reminder. Refusing would be unhelpful; silently re-enabling would defeat `off`.
- **`.ai/` is never deleted or reset** by on/off: the state survives so `on` is lossless.
- **`project-phase on` rebuilds the block from `.ai/phase.md`**, the same way setup does. Consequence: hand edits to the block would be lost, so `off` first moves bullets not derivable from the contract or `phase.md` into `## Custom rules`. This is the only write to `.ai/` that on/off does.
- **`work-journal on` writes the fixed block** (it has no project state).
- **`@AGENTS.md` in `CLAUDE.md` is left in place on `off`**: other blocks or content may need it.

## Evals

- Evals 6-8 (`journal-off-csv`, `phase-on`, `phase-off-it`) cover: off respected during normal work, on rebuilding from `phase.md`, off moving hand edits to `phase.md`.
- Their fixtures have a `state-in-baseline` flag, so `without_skill` gets the same `AGENTS.md` and `.ai/`. Otherwise the baseline would have no block to turn on or off and the comparison would say nothing; this way it measures what the skill adds over an agent reading the same files.
- Evals 8-10 are in Italian, French and German, because the descriptions only list English trigger phrases and the users of this repo mostly don't write in English. 9 and 10 reuse the fixtures and graders of 3 and 4, so any gap against them is the language.
- The fixtures reuse `base/` and `history.txt` of existing ones through symlinks, so there is no copied source to keep in sync.

## Language

Triggers worked in Italian, French and German without non-English examples in the descriptions, so the descriptions stay English-only. But in eval 8 the agent did the work correctly and replied in English to an Italian request (the baseline replied in Italian): the English skill text pulled the reply language. Both skills now say: talk in the user's language; files keep the language they already use, new ones in English. Forcing files to English was discarded because a team that already writes its journal in German should not get mixed-language files.

## Alternatives discarded

- *Delete the block only*: the skill re-adds it (see Why).
- *Store the off state in `.ai/phase.md` or a `.ai/config` file*: work-journal has no state file of its own, and the skill would need an extra read on every trigger; `AGENTS.md` is already in context.
- *Comment the block out*: the block contains HTML comments, which don't nest, and a commented-out block still costs context.
- *A global off switch*: per-project is what the marker can express; globally, uninstalling the skill is the off switch.
